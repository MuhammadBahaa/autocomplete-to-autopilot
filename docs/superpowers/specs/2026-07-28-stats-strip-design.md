# Stats strip ("The toolbox") — design

**Date:** 2026-07-28
**Status:** Approved — look: stat tile row · data: per-milestone `stats` field · categories: all six

## Goal

Show totals of what the timeline's work produced — skills, plugins, agents, commands, scripts, courses — at the top of the page. The totals are derived from the milestone entries themselves, so the numbers can never drift from the timeline: delete a milestone and its contribution disappears with it.

## Data model

Each milestone entry in `milestones.js` may carry an optional `stats` object:

```js
stats: { skills: 2, plugins: 1 }   // any subset of the six keys
```

- Recognized keys: `skills`, `plugins`, `agents`, `commands`, `scripts`, `courses`.
- Values are positive integers. Zero, negative, non-numeric values and unknown keys are ignored at render time.
- Entries with nothing countable omit the field entirely.
- The field records what that milestone produced, once. Umbrella or summary entries stay empty so nothing is counted twice.
- Documented in the template comment at the top of `milestones.js` and in the README's "Add a milestone" section.

## Rendering

- The inline script in `index.html` sums each recognized key across all entries.
- A tile row renders directly below the tagline and above the sticky month nav. The markup is generated by JS into a container element, so a no-JS page shows nothing extra.
- Fixed display order: Skills, Plugins, Agents, Commands, Scripts, Courses.
- Tile look: big number in Bricolage Grotesque 800, small uppercase Spline Sans Mono label (same letter-spacing treatment as `.counter`), card colors from the timeline (`#1C1630` background, `#35294F` border), rounded corners, `rise` entrance animation.
- Layout: CSS grid with `auto-fit` columns so six tiles sit in one row on desktop and wrap to 3 or 2 columns on narrow screens.
- Count-up: numbers animate 0 → total over ~800 ms with an ease-out curve on load. Under `prefers-reduced-motion: reduce` the animation is skipped and final values render immediately.
- A category totalling zero renders no tile. If every total is zero (no entry has `stats`), the whole section stays hidden — the page looks exactly like today.

## Capture at entry time

- **Milestone Composer** (`tools/composer-template.html`): a "What did this build?" row with six small number inputs. The generated snippet includes `stats` only when at least one value is above zero, and lists only the non-zero keys. Loading an existing entry for editing fills the inputs from its `stats`; the edit round trip preserves them.
- **Claude Code entry:** when asked to add a milestone, the counts are taken from the request (or asked for) and written into the entry.
- **Manual GitHub/local edits:** covered by the template comment and README.

## Error handling

- Malformed `stats` (wrong types, unknown keys) is ignored silently — the page must never break because of a bad stats value; worst case a tile is missing.
- File-level syntax errors keep the existing "couldn't load milestones" fallback.

## Testing

Manual verification in the browser via a local server:

1. Tiles render with the seeded totals in the fixed order; zero categories are absent.
2. Removing all `stats` fields hides the whole section.
3. Reduced-motion shows final numbers with no animation.
4. Composer: an entry with counts emits a correct `stats` field; an entry without counts emits none; editing an entry with `stats` round-trips it.
5. Existing features are unaffected: month nav, lightbox, unlock counter.

## Out of scope

- No stats chips or badges on the timeline cards (they were deliberately removed before).
- No new files, frameworks, or build steps.
- No drill-down or filtering by category.
